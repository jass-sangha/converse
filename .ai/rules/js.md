# Js

## useEcho() must never throw uncaught
`new Echo({ broadcaster: 'reverb', ... })` (via pusher-js) throws synchronously when Reverb isn't configured (e.g. missing key) in the current environment. Because `useEcho()` is called from inside other synchronous call sites — `useTyping().notifyTyping/stopTyping`, `App.vue`'s `onMounted`, `ChatWindow.vue`'s conversation watcher — an uncaught throw there aborts the rest of that calling function, which silently breaks unrelated features: the composer's `submit()` never reaches `send()` (messages can't be sent), `App.vue`'s `ensureSelfCached()` never runs (profile avatar/name never loads, shows "?"), and `ChatWindow`'s `load(newId)` never runs (message history never loads). `useEcho()` in `resources/js/composables/useEcho.js` wraps `new Echo(...)` construction in try/catch and falls back to a `noopEcho` object (chainable no-op `.listen()`/`.whisper()`) so a missing/broken broadcasting config only disables realtime push — REST-based send/load/typing keep working. Keep that guard in place; don't let `new Echo(...)` throw uncaught again.

## Icons go through the registry, not inline `<svg>`
Every icon glyph (mic, trash, search, send, star, etc.) is registered by name in `resources/js/icons/defaults.js` and rendered via `<Icon name="..." :size="20" />` (`resources/js/components/shared/Icon.vue`), which looks it up in `resources/js/icons/registry.js`. This exists so a host app can swap any icon at runtime — via the published `public/vendor/chat/icons.js` (see `resources/js/icon-overrides.js`, tag `chat-icons`) or `config('chat.theme.icons')` — without rebuilding the bundle (mirrors the theme.css / `config('chat.theme.overrides')` color/radius/font/shadow override system). Don't add a new inline `<svg>...</svg>` block to a component; register it in `defaults.js` under a semantic name and use `<Icon>` instead. Exceptions that legitimately stay inline: SVGs whose path data is bound to per-item business data (e.g. `EmojiPicker.vue` category icons, `AttachmentPicker.vue` option icons — keyed by arbitrary data, not a fixed theme icon), and state-driven icon swaps should register each state as its own named variant (e.g. `mic` / `mic-muted`) selected via a computed `:name`, not left as a `v-if`/`v-else` chain of raw `<svg>` tags.
Radius (`rounded-chat-sm/chat/chat-lg/chat-xl`) and shadow (`shadow-chat`/`shadow-chat-lg`) utilities are similarly tokenized — don't reintroduce hardcoded `rounded-[Npx]` or raw Tailwind `shadow-sm/lg/xl/2xl`; use the `chat-*` scale so those stay themeable via the same CSS-variable system (`resources/css/theme.css`).

## Wallpaper patterns/colors go through the registry too
`resources/js/wallpapers.js` exposes `registerWallpaperPatterns()`/`registerWallpaperColors()` (Map-based, same shape as the icon registry) instead of the old static `WALLPAPER_PATTERNS`/`WALLPAPER_COLORS` exports — read them via `getWallpaperPatterns()`/`getWallpaperColors()`. Overridable the same way as icons: `config('chat.theme.wallpapers')` for quick tweaks, or publish+hand-edit `public/vendor/chat/wallpapers.js` (`--tag=chat-wallpapers`, source at `resources/js/wallpaper-overrides.js`) for full control. Don't add a new pattern/color as a bare array literal in `WallpaperPicker.vue` — register it in `wallpapers.js` under a `key` instead, so hosts can still override it.
