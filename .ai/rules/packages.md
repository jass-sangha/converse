# Packages

## Converse chat package: polymorphic chatables, no user_id
The `jass-sangha/converse` package (in packages/) never stores a plain `user_id`. Every chat_* table uses polymorphic `chatable_type`/`chatable_id` columns, backed by a Laravel morph map registered from `config('chat.chatable_models')` (alias => Authenticatable model class, e.g. `'user' => App\Models\User::class`). Repositories/services/contracts take the actual `Illuminate\Database\Eloquent\Model` instance as the actor (e.g. `Model $chatable`), never a bare int id — use `Chat::identify()`/`Chat::whereChatable()`/`Chat::resolveChatable()`/`Chat::resolveMany()` helpers (packages/src/Chat.php) instead of hand-rolling type+id comparisons. API routes/requests reference a chatable as `{type}/{id}` in URLs and `{"type": ..., "id": ...}` in request bodies — never `{userId}` or a bare `user_id` field. Laravel Sanctum is a direct dependency of the package's own composer.json (not the host app's) — ChatServiceProvider self-registers the `EnsureFrontendRequestsAreStateful` middleware, so the host app needs zero bootstrap/app.php or composer.json changes for chat auth to work. The bundled Vue UI under packages/resources/js has been updated to match: it identifies chatables by a `"type:id"` composite string (see packages/resources/js/chatable.js's `chatableKey()`/`chatableKeyOf()`), never a bare id — the store (packages/resources/js/store/index.js) keys `usersById`/`presenceByUser`/`typingByConversation` by that composite key, and `store.currentType`/`currentId`/`currentKey` (set via `setCurrentChatable()`) replace the old single `currentUserId`. After editing any file under packages/resources/js, run `npm install && npm run build` inside packages/ to regenerate the committed `packages/resources/dist/app.{js,css}` — the dist files are what actually get served, so source edits alone have no effect until rebuilt.

## Media disk root must live under storage/app/public
The package's default `chat` filesystem disk (registered in `ChatServiceProvider::registerDefaultDisk()`, used for avatars and message attachments) must have its `root` nested inside `storage/app/public/...`, not `storage/app/...`. Laravel's dev-server-only `storage/{path}` route (`storage.local`, provided by the framework when no `public/storage` symlink exists) validates the resolved real path stays inside `storage/app/public` and returns a bare 403 for anything outside it — so a disk rooted at `storage/app/chat` makes every avatar and attachment URL 403 in local dev, with no obvious error pointing at the cause. Keep the disk's `root` under `storage/app/public/chat` (already fixed to `storage_path('app/public/chat')`) and make sure `php artisan storage:link` has been run so `public/storage` actually points at `storage/app/public`.
